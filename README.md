# Технология тепла — сайт

Одностраничный сайт компании «Технология тепла» (Санкт-Петербург и Ленинградская область):
проектирование и монтаж отопления, тёплых полов, котельных и водоснабжения в частных домах.

Весь контент, фотографии объектов и чертежи взяты из презентации
«5 решений при установке и монтаже отопления, которые ведут к переплатам».

## Что внутри

```
index.html                  вся разметка главной страницы
privacy/index.html          политика обработки персональных данных
send-lead.php               приём заявок и отправка их на почту
.htaccess                   редиректы на https, сжатие и кеширование
sitemap.xml, robots.txt     карта сайта для поисковиков
assets/css/styles.css       стили, палитра и адаптивность
assets/js/script.js         меню, док, аккордеон, галерея, лайтбокс, формы
assets/img/                 иконки, логотип и чертежи из презентации
assets/img/projects/        17 фотографий объектов (полный размер + превью)
tools/extract_pdf_assets.py извлечение и оптимизация картинок из PDF
tools/contact_sheet.py      контрольный лист картинок для ревизии
tools/preview/              превью страниц PDF и контрольный лист (не выкладываются)
```

На хостинг уходят только `index.html` и `assets/` — это около 8 МБ. Папка `tools/`
нужна лишь при пересборке картинок.

## Как запустить

Сайт статический, сборка не нужна. Достаточно открыть `index.html` в браузере.

Чтобы всё работало ровно так же, как на хостинге (относительные пути, кеширование),
удобнее поднять локальный сервер:

```bash
python -m http.server 8123
```

Затем открыть <http://127.0.0.1:8123/>.

## Публикация

Боевой адрес: <https://inergo-sistemy.ru/>

Сайт лежит на хостинге Beget, аккаунт `sgorongo`, в директории
`~/inergo-sistemy.ru/public_html`. Там же работает PHP, поэтому заявки уходят письмом
по-настоящему. Домен привязан к сайту в панели (Сайты → Attach domain), SSL — бесплатный
сертификат Beget, `http` и `www` редиректятся на `https://inergo-sistemy.ru`
правилами из `.htaccess`.

Обновление — заливка изменившихся файлов по FTP на `sgorongo.beget.tech`
в ту же директорию. Выкладываются только `index.html`, `send-lead.php`, `.htaccess`
и папка `assets`; `tools/`, `audit/` и README на хостинге не нужны.

Запасная копия статики автоматически живёт на GitHub Pages:
<https://sgoronkov.github.io/inergo-sistemy/> — обновляется пушем в `master`.
Там PHP нет, поэтому формы на этой копии работают через запасной путь
(см. раздел «Заявки»).

Если сайт когда-нибудь переедет на другой домен, поправьте в `index.html`
`<link rel="canonical">`, `og:url` и `og:image`, в `send-lead.php` — константу
`LEAD_FROM`, а в `.htaccess` — адрес в правиле редиректа.

## Заявки

На сайте две формы, и обе отправляют данные в одно место:

- **попап** — открывается по любой кнопке с классом `js-open-lead` (шапка, первый экран,
  блок выводов, плавающая кнопка, пункт в мобильном меню). Спрашивает только имя и телефон;
- **подробная форма** в секции «Заявка на расчёт» — дополнительно площадь, состав работ
  и комментарий.

Обе проверяют поля в браузере: имя обязательно, телефон приводится к формату
`+7 XXX XXX-XX-XX` и должен содержать 11 цифр, нужна галочка согласия. У каждой формы есть
скрытое поле `website` — приманка для ботов: люди его не видят, а автозаполнение ботов
попадается, и такая заявка отбрасывается на сервере.

Дальше данные уходят POST-запросом в `send-lead.php`, который проверяет их ещё раз
и отправляет письмо. Получатель задан константой `LEAD_RECIPIENT` в начале файла:

```php
const LEAD_RECIPIENT = 'sgoronkov@yandex.ru';
```

Там же поправьте `LEAD_FROM` — подставьте адрес на вашем домене, иначе почтовые сервисы
могут отклонить письмо из-за несовпадения отправителя.

**Что нужно от хостинга:** PHP с работающей функцией `mail()`. Если хостинг статический
(GitHub Pages, Netlify) или PHP отключён, запрос не пройдёт — тогда скрипт не теряет заявку,
а собирает её в письмо и открывает почтовую программу посетителя. Это запасной путь,
для продакшена лучше поднять PHP или заменить `LEAD_ENDPOINT` в `assets/js/script.js`
на адрес стороннего обработчика форм.

## Контакты и мессенджеры

Телефон, WhatsApp, MAX и почта заданы константами в начале `assets/js/script.js`
(`PHONE`, `WHATSAPP`, `MAX_CHAT`, `EMAIL`) и продублированы ссылками в `index.html`.
На мобильных внизу экрана закреплён док: слева кнопка «Связаться» разворачивает
звонок, WhatsApp, MAX и почту, справа — полноэкранное меню с кнопкой заявки.

С MAX есть нюанс: в нём нет ссылок по номеру телефона, как `wa.me` у WhatsApp.
Нужна личная ссылка вида `https://max.ru/u/...` — её берут в приложении
(Профиль → QR-код → Поделиться) и подставляют в `MAX_CHAT`. Все кнопки MAX,
включая ссылку в блоке контактов, берут адрес из этой константы.

## Страницы и поисковики

Кроме главной есть `/privacy` — политика обработки персональных данных, на неё ведут
ссылки из обеих форм согласия и из подвала. Адрес отдаётся без слеша на конце: этим
занимаются `DirectorySlash Off` и правило перезаписи в `.htaccess`, иначе Apache
редиректил бы на `/privacy/`, причём по http.

Обе страницы перечислены в `sitemap.xml`, на который ссылается `robots.txt`.
При добавлении новых страниц не забудьте дописать их туда.

Адреса стилей и скрипта содержат версию (`?v=20260806`), потому что `.htaccess`
кеширует их на неделю. После правок в CSS или JS поднимайте эту версию в `index.html`
и `privacy/index.html`, иначе вернувшиеся посетители увидят старые файлы.

## Пересборка картинок из PDF

Если презентация обновится, картинки можно перегенерировать:

```bash
pip install pymupdf pillow
python tools/extract_pdf_assets.py
```

Скрипт рендерит превью страниц, вытаскивает изображения вместе с их альфа-масками,
сохраняет иконки в PNG с прозрачностью, а фотографии сжимает в JPEG до 1400 px
(и дополнительно делает превью 700 px для сетки галереи). Путь к PDF задан
константой `PDF_PATH` в начале скрипта.

Соответствие «номер объекта в PDF → имя файла» задано словарями `ICONS`, `DESIGNS`
и списком `PHOTO_XREFS`. Если состав презентации изменится, эти списки нужно обновить —
посмотреть, что и под каким именем извлеклось, помогает контрольный лист:

```bash
python tools/contact_sheet.py projects 5
```

## Зависимости

У самого сайта зависимостей нет — только HTML, CSS и JavaScript без библиотек.

Python-скрипты в `tools/` нужны лишь для подготовки картинок:

| Пакет   | Версия | Зачем                                          |
| ------- | ------ | ---------------------------------------------- |
| pymupdf | 1.28+  | чтение PDF, извлечение изображений и альфа-масок |
| pillow  | 12.0+  | изменение размера и сжатие в JPEG/PNG          |

Установка: `pip install -r requirements.txt`
